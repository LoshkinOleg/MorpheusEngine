- Tokenizer: "The gist is three steps:

**Grab the tokenizer file** from the HuggingFace repo `Qwen/Qwen3-4B-Instruct-2507`. You only need `tokenizer.json` — it's the self-contained BPE definition (vocab + merge rules + special tokens all in one). Commit it into your MorpheusEngine repo as a bundled asset, something like `Resources/Tokenizers/qwen3-4b-instruct-2507.json`.

**Add Microsoft.ML.Tokenizers** via NuGet. The package can load HuggingFace-format `tokenizer.json` files directly. You'd initialize it once at engine startup, roughly: `Tokenizer.CreateTiktokenForEncoding(...)` — actually for HuggingFace BPE it's more like `Tokenizer.CreateBpe(...)` or loading from the JSON. You'll want to verify the exact API surface since this library has been evolving; check the latest docs. The key method you care about is `CountTokens(string text)` or `EncodeToIds(string text).Count`.

**Wire it into your turn pipeline.** Create a thin `ITokenCounter` interface with a `int CountTokens(string text)` method, backed by the ML.Tokenizers implementation. Use it in your context assembly phase — as you pack system prompt, memory blocks, conversation history, and tool schemas into the working context, you call `CountTokens` on each segment and track the running total against your budget (model's context length minus reserved output tokens). This also lets you swap tokenizers later if you switch models, without touching the pipeline logic.

One thing to validate early: after you've got it loaded, send a few test strings through both your local tokenizer and an actual Ollama inference call (the response includes `prompt_eval_count` which tells you how many tokens Ollama saw in the prompt).
